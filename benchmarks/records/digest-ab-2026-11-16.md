# Three general rules in the digest: an A/B on plain SoMi (2026-11-16)

The digest is what makes plain SoMi better than a bare agent: with it switched off, SoMi dropped from 8 of 10 to 2 of 6 on the hardest
small tasks. The staged workflow had found general habits that close real gaps, so three of them were written into the digest, on the
branch `exp/digest-lessons` (2c251b4):

- read how the codebase already does the same kind of thing, and follow it; new code goes through the layer that owns the data, and
  reuses what exists instead of copying it;
- done means every line of the request is built and tested, so read it again line by line before saying so;
- test each new input left out, of the wrong type, and at and just past each limit.

None names a task or a trap.

## Method

Plain SoMi on Sonnet, at release/next (efce24b) against the same with the three rules, two draws each on 12 tasks: four of the hardest
small ones and the eight medium ones. 24 draws per arm. Then the same independent Opus reviewer as in the
[gate study](../quality/records/gate-escapes-2026-11-15.md) read one draw of each medium task in each arm.

## Results

| | without the rules | with the rules |
|---|---|---|
| Hidden tests pass | 17/24 | 16/24 |
| Own tests valid | 13/24 | 16/24 |
| Strict successes (hidden tests, valid own tests and the gate) | 8/24 | 11/24 |
| Dollars per draw | 0.415 | 0.385 |
| Reviewer's mean grade, 8 medium changes | 3.1 | 3.1 |
| Changes with a blocking issue | 7 of 8 | 5 of 8 |

- **Hidden-test solves did not move.** The arms differ by one draw, on different tasks each way.
- **Own tests and strict successes rose by three each.** The rule about testing each input at its edges is the likely cause, but 24
  draws per arm cannot separate that from chance.
- **The fifth-kind task (MD8) passed the gate with the rules.** Without them the kind was copied, and the gate failed it.
- **It cost 7% less per draw.**
- **The reviewer's view did not change much.** The audit tasks were blocked in both arms for writing a revert straight to the store,
  a design the task admits on purpose, so that verdict is the reviewer's own view.

## What it says

The rules do not hurt, and they may help where SoMi is held to more than hidden tests. That is not enough to ship a change to the
digest, which decides the small segment's ship rule. A run on the small segment's registered tasks, at its full number of draws,
would settle it. The branch stays unmerged until then.

## The small segment

Plain SoMi on all 16 registered small tasks, 3 draws each, with and without the rules. Same models and pin as above.

| | without the rules | with the rules |
|---|---|---|
| Hidden tests pass | 42/48 | 46/48 |
| Own tests valid | 34/48 | 37/48 |
| Strict successes | 31/48 | 35/48 |
| Dollars per draw | 0.196 | 0.186 |

- **The gains sit on three tasks.** N10 and N17 went from 1 of 3 to 3 of 3, H4 from 2 to 3. H1 lost one draw (3 to 2). The other
  twelve tasks were the same in both arms.
- **No task got worse by more than one draw, and it cost 5% less per draw.**
- **Across both runs** strict successes are 46 of 72 with the rules and 39 of 72 without. Every measure but medium hidden-test solves
  moved the same way. At 3 draws per task this is a consistent direction, not a significant result.

## What it says now

The rules help or do no harm on every measure in both segments, at lower cost. Merging them into the digest is the maintainer's
decision; the evidence supports it, and a full recording after the merge would confirm it at the full number of draws.
