# Usage and speed evidence report: 6cced12 against 03c1f76

A cost-saving attempt inside 4.1.0, measured against 4.1.0 as it stood before it. Three changes, measured
together: the run card (`scripts/somi-card.mjs`, pasted first in every `/code-loop` briefing), the
orchestrator no longer reading or editing the iteration's code or running its tests, and flows naming
`${CLAUDE_PLUGIN_ROOT}` so the orchestrator stops searching the disk for SoMi's scripts. Procedure:
[`docs/USAGE-BENCHMARK.md`](../../../docs/USAGE-BENCHMARK.md).

**Result: no measurable cost saving.** The primary metric is inconclusive, and the SoMi arm's absolute cost
did not move.

The orchestrator limits did what they say: on S3 the main thread no longer does the coding, and its cost fell a
quarter while the coder's rose by about the same amount. The run card shows no saving: the coder's and reviewer's
turns did not fall, and printing the card is one more main-thread step (S1). Searching for the install root is
gone from the transcripts. The three were measured together, so this split is inference, not measurement.

## Limits

- Per release, not per commit: the result covers every change in the release together.
- The verdict is for the recorded model tier only; context-size effects transfer in direction, sizing and
  other behaviour effects do not.
- L0 is exact bytes injected, not tokens billed. L1 is one host fingerprint. Live L2 resolves only large
  changes (about 50% or more); smaller changes read inconclusive by design.
- Quality is a coarse non-inferiority flag only; no quality win or loss is declared.
- The three changes were recorded as one candidate; their separate effects are not measured.
- The run card's other intended effect, a byte-stable briefing prefix reused across passes, cannot show on
  these scenarios: their loops mostly approve in one pass, so there is rarely a second coder or reviewer start.
