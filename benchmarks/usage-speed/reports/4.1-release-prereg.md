# Pre-registration: the 4.1 release candidate against 6cced12

Written 2026-11-02, before any paid (L2) row of the candidate exists. The release report that follows the paid runs
cites this file and may not change what it fixes.

## What is compared

- Candidate: the commit that adds this file (the frozen 4.1 release candidate). The plugin under test is exported
  with `git archive`, tests and benchmarks excluded, so this file is not part of what is measured.
- Baseline: [`baseline-6cced12.json`](../baseline-6cced12.json), the same baseline the loop-step measurement used
  ([`loop-step-mcp-prereg.md`](./loop-step-mcp-prereg.md), [`e376e98-vs-6cced12.md`](./e376e98-vs-6cced12.md)).
- Model alias `haiku`, tier `low`, every agent pinned, the same host as the baseline.
- Scenarios S1, S2, S3, 8 seeds each, one repeat per chunk, caps `--budget-total 3 --budget-somi 2 --budget-bare 1`
  per draw as in the baseline and the loop-step run.

## What the release changes, as it bears on usage

- `/code-loop` and `/plan-loop` run each transition through the `somi_loop` MCP tool (measured on e376e98).
- The code step now also computes and reports a review escalation from the diff (report-only: it changes no review
  mode or level). It adds work to the main thread on every code pass, so it can only cost, not save.

## Metrics, fixed now

- **Primary: `cost`**, dollars per draw, SoMi against bare, per scenario and pooled.
- **Alongside: `time`**, wall-clock per draw.
- **Diagnostics, not verdicts:** `turns` and `tokens`, and the S1 main-thread median beside e376e98's 16 turns and
  117k weighted tokens, to show whether the report-only escalation erased the loop-step gain.
- The quality guard must be clear. An inconclusive cost verdict is published as inconclusive with the figures in full.

## Budget and go-ahead

The user gave the go-ahead on 2026-11-02: a smoke of two S1 draws (worst case $6), then the 24 chunks (worst case
$72). The bench authenticates with the subscription token, so the dollar figures are the CLI's cost estimate; the
binding limit is the account's usage window, and nothing else heavy runs during the recording.
