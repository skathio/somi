### The two S2 draws at 0/31

Both are sizing, not a broken flow. Stage -1 sized T1 `full` in 3 of 8 candidate draws (draws 3, 4 and 5)
against 0 of 8 in the baseline; each gave an estimate of about 110 production lines against the
100-line threshold. A `full` run goes through `/plan-loop`, whose planner stops at its design decisions,
and an unattended draw has no one to answer: draws 4 and 5 ended asking for that answer; draw 3 got
through. 3 of 8 against 0 of 8 is not significant at eight draws, and the boundary has flipped on this task
before, but it is reported rather than dismissed.

Draw 4 also shows a behaviour the release did not intend: the main thread running `/ship-loop` started a
`somi-flow` subagent for `/plan-loop` instead of running that procedure inline. It did not change the
outcome (the planner's decisions stop the run either way), and it is addressed after this measurement.

## Limits

- Per release, not per commit: the result covers every change in the release together.
- The verdict is for the recorded model tier only; context-size effects transfer in direction, sizing and
  other behaviour effects do not.
- L0 is exact bytes injected, not tokens billed. L1 is one host fingerprint. Live L2 resolves only large
  changes (about 50% or more); smaller changes read inconclusive by design.
- Quality is a coarse non-inferiority flag only; no quality win or loss is declared.
- L2 drives Claude Code only. The release's main claim, that the Copilot front door dispatches instead of
  doing the work, is behavioural and outside every layer here; its evidence is the live Copilot CLI runs in
  the 4.1.0 CHANGELOG entry.
- The candidate's L0 scenario components count the flow and role skills its commands and agents load;
  the scenario ids are unchanged (see [`6e4701a-vs-c2723eb.md`](./6e4701a-vs-c2723eb.md)).
